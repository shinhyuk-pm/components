# 확장하기

라이브러리가 못 하는 화면은 반드시 나옵니다. 그때 우회해서 따로 만들면
공통성이 무너집니다. 그래서 **일탈을 막지 않고 라이브러리로 흡수시킵니다.**

흡수 경로는 세 가지이고, 아래로 갈수록 비용이 큽니다. 위에서부터 시도합니다.

---

## 1단계 — 토큰만 바꾼다

"버튼만 더 둥글게", "카드 그림자를 더 강하게" 같은 요구입니다.

`styles/tokens/tier3.css` 에 해당 토큰이 있는지 봅니다. 있으면 스킨에서 그 값만
덮어씁니다. 컴포넌트는 건드리지 않습니다.

없으면 tier3 에 토큰을 하나 추가하고 컴포넌트가 그것을 읽도록 한 줄 고칩니다.
이때도 컴포넌트에 값을 적지는 않습니다.

---

## 2단계 — 배치 프리셋을 추가한다

"아이콘을 오른쪽으로", "값을 라벨 위로" 같은 요구입니다.

`styles/layouts/<컴포넌트>.css` 에 선택자를 하나 추가합니다.

```css
[data-slot="stat-card"][data-layout="value-first"] {
  display: flex;
  flex-direction: column-reverse;
  gap: var(--t3-pad-1);
}
```

그리고 컴포넌트의 layout 타입에 이름을 더합니다.

```ts
type StatCardLayout = "stacked" | "icon-left" | "horizontal" | "value-first";
```

**계약은 건드리지 않습니다.** 슬롯의 이름과 개수가 그대로이므로
기존 화면 명세가 전부 그대로 동작합니다.

---

## 3단계 — 새 페이지 원형을 추가한다

`handoff` 가 여러 번 쌓인 주제는 새 원형의 후보입니다.
같은 사유가 세 번 이상 나오면 원형으로 만듭니다.

절차는 다섯 가지입니다.

1. `lib/screen-spec.ts` 에 타입을 추가하고 `ARCHETYPES` 에 이름을 넣는다
2. 같은 파일의 `validateScreenSpec` 에 필수 항목 검사를 추가한다
3. `components/blocks/screen.tsx` 에 렌더 함수를 만들고 분기에 연결한다
4. `lib/component-catalog.ts` 에 **쓸 때 / 쓰지 말 때** 를 적는다
5. `app/llms.txt/route.ts` 에 구조 설명을 추가한다

4번과 5번을 빠뜨리면 AI가 새 원형의 존재를 모릅니다. 가장 자주 잊는 단계입니다.

---

## 어떤 경우에도 지키는 것

**컴포넌트에 디자인 값을 적지 않습니다.** 색, 모서리, 그림자, 테두리 두께는
전부 토큰을 경유합니다. `npm run verify` 가 이것을 검사합니다.

**계약을 깨지 않습니다.** 슬롯의 이름과 개수를 바꾸면 기존 화면 명세가
전부 무효가 됩니다. 바꿔야 한다면 새 컴포넌트를 만드는 편이 낫습니다.

**설명서를 함께 갱신합니다.** 부품을 늘리는 것보다 설명을 정확히 쓰는 것이
에이전트 품질에 더 크게 기여합니다.
