# 확인 방법

개발 지식 없이 브라우저만으로 전부 확인할 수 있도록 정리했습니다.
위에서부터 순서대로 하시면 됩니다. 각 항목에 **통과 조건**이 있습니다.

확인할 곳은 두 군데뿐입니다.

- **배포된 화면** — Vercel 주소
- **GitHub** — 코드와 자동 검사 결과

---

## 준비 — 배포 주소 찾기

1. https://vercel.com 접속
2. `components` 프로젝트 클릭
3. 오른쪽 위 **Visit** 버튼 클릭

여기서 나온 주소가 앞으로 계속 쓰는 확인 창구입니다. 즐겨찾기에 넣어두세요.

---

## 1. 안전장치가 작동하는가 (Phase 0)

**왜 확인하나** — 컴포넌트에 색을 직접 쓰면 디자인 교체가 깨집니다.
그걸 기계가 막고 있는지 봅니다.

**어디서** — GitHub 저장소 → 상단 **Actions** 탭

**무엇을 보나** — 목록에 `verify` 라는 검사 기록이 쌓여 있습니다.
아무거나 하나 클릭하면 검사 항목들이 나옵니다.

**통과 조건**
- 항목 이름에 "하드코딩된 디자인 값 차단" 이 있다
- 초록 체크 표시다

과거에 일부러 위반한 코드로 만든 Pull Request(#2)에서 빨간 X가 떴던 것이
이 장치가 실제로 막는다는 증거입니다.

---

## 2. 디자인이 통째로 바뀌는가 (Phase 1)

**왜 확인하나** — 이 프로젝트 전체의 전제입니다. 이게 안 되면 나머지가 무의미합니다.

**어디서** — 배포된 화면 맨 위 **디자인** 카드

**무엇을 하나**
1. `와이어프레임` 버튼 클릭 — 회색조의 밋밋한 화면
2. `핀테크 B2B` 클릭 — 파란 계열, 좁은 여백
3. `감성 커머스` 클릭 — 따뜻한 색, 둥근 모서리, 넓은 여백, 세리프 제목
4. `야간 관제 콘솔` 클릭 — 어두운 배경

**통과 조건**
- 네 가지가 서로 완전히 달라 보인다
- 글자가 잘리거나 밖으로 넘치는 곳이 없다
- 어두운 배경에서도 글자가 잘 읽힌다
- 버튼을 눌러도 화면 구조(어떤 항목이 어디 있는지)는 그대로다

**중요** — 이 네 가지는 컴포넌트 코드를 한 줄도 다르게 쓰지 않았습니다.
바뀐 것은 스킨 표뿐입니다.

---

## 3. 배치가 바뀌어도 내용은 그대로인가 (Phase 2)

**왜 확인하나** — 디자이너가 "이 카드를 가로로 눕혀줘" 했을 때
기획 문서를 다시 안 써도 되는지 봅니다.

**어디서** — **화면 하나** 탭

**무엇을 하나**
1. `목록형` 버튼 클릭
2. 오른쪽 상단 통계 카드 세 개를 봅니다 — 라벨, 숫자, 증감이 들어 있습니다
3. 위쪽 디자인을 `감성 커머스` 로 바꿔봅니다

**통과 조건**
- 카드 안에 **라벨·숫자·증감** 세 가지가 항상 있다
- 스킨이 바뀌어도 그 세 가지가 사라지거나 늘어나지 않는다

배치 프리셋 자체는 `styles/layouts/` 폴더에 있습니다.
대시보드는 `icon-left`, 목록은 `stacked` 로 서로 다른 배치를 쓰고 있습니다.
**프로젝트 전체** 탭에서 대시보드와 회원 목록의 카드 모양을 비교해보시면
같은 계약에 다른 배치가 적용된 것을 볼 수 있습니다.

---

## 4. 문서 하나로 화면이 나오는가 (Phase 3)

**왜 확인하나** — 기획 문서가 와이어프레임과 디자인까지 그대로 흘러가는지 봅니다.
이 구상의 핵심 주장입니다.

**어디서** — **화면 하나** 탭

**4-1. 문서를 고쳐봅니다**
1. `목록형` 버튼 클릭
2. 왼쪽 글상자에서 `"title": "회원 관리"` 를 찾아 `"회원 조회"` 로 바꿉니다
3. 오른쪽 화면의 제목이 즉시 바뀝니다

**4-2. 일부러 틀려봅니다**
1. `"archetype": "list"` 를 `"archetype": "kanban"` 으로 바꿉니다
2. 오른쪽 화면이 사라지고 왼쪽 아래에 이유가 나옵니다

**통과 조건**
- 문서를 고치면 화면이 바로 바뀐다
- 틀린 문서를 넣으면 화면을 그리지 않고 **한국어로** 이유를 알려준다
- 그 이유를 읽고 무엇을 고쳐야 하는지 알 수 있다

**4-3. 가장 중요한 확인**
1. `목록형` 을 다시 누릅니다
2. **왼쪽 문서는 손대지 않고** 위쪽에서 디자인만 `야간 관제 콘솔` 로 바꿉니다

**통과 조건** — 문서를 한 글자도 안 고쳤는데 디자인이 완전히 달라진다.

---

## 5. AI가 디자인을 만드는가 (Phase 4)

**먼저 API 키가 필요합니다.** 없으면 5-1은 건너뛰고 5-2만 확인하세요.

키 등록 방법: Vercel → `components` → **Settings** → **Environment Variables**
→ 이름 `ANTHROPIC_API_KEY`, 값은 Anthropic 콘솔에서 발급받은 키 → 저장 후 재배포

**5-1. 서비스 설명으로 디자인 만들기**
1. 맨 위 디자인 카드의 입력칸에 이렇게 씁니다
   `친환경 농산물 직거래 앱, 따뜻하고 편안하게`
2. `AI로 만들기` 클릭

**통과 조건**
- 몇 초 뒤 화면 전체의 색과 느낌이 바뀐다
- 그 설명에 어울리는 방향으로 바뀐다 (따뜻한 색, 넉넉한 여백)
- 글자가 안 읽히는 곳이 없다

**같은 문장으로 3번 눌러보세요.** 결과가 매번 크게 달라지면
부품 설명서를 다듬는 추가 작업이 필요합니다. 이게 Phase 4의 진짜 판정입니다.

**5-2. 대비가 보장되는지 확인**

디자인 카드 아래에 이런 줄이 있습니다.

```
대비 검사 통과 — 본문 / 배경 12.5 · 보조 / 배경 4.8 · ...
```

숫자가 기준(본문 4.5, 보조 3.0) 이상이면 글자가 읽힌다는 뜻입니다.
어떤 디자인을 골라도 이 숫자가 기준 아래로 내려가지 않습니다.

**어디서 더 확인하나** — GitHub → Actions → 최근 `verify` → "스킨 대비 전수 검사"

```
skin-check: 통과 (조합 5760개, 대비 검사 28800건)
```

가능한 디자인 조합 5,760가지를 전부 검사한 결과입니다.

## 6. 프로젝트 하나가 통째로 나오는가 (Phase 5)

**왜 확인하나** — 화면 하나가 아니라 실제 규모의 프로토타입이 나오는지 봅니다.

**어디서** — **프로젝트 전체** 탭

**무엇을 하나**
1. 왼쪽 사이드바에서 항목들을 하나씩 눌러봅니다
   - 대시보드 / 회원 목록 / 회원 상세 / 회원 등록 / 쿠폰 목록 / 쿠폰 발행 / 설정
2. 위쪽 디자인을 바꿔가며 다시 둘러봅니다

**통과 조건**
- 일곱 개 화면이 모두 나온다
- 사이드바 메뉴 구조가 기획서의 목차와 같다
- 화면 위쪽에 현재 위치(예: 회원 › 회원 목록)가 표시된다
- 표에 이름·이메일·날짜·금액 같은 그럴듯한 값이 채워져 있다
- 디자인을 바꿔도 일곱 화면이 모두 같이 바뀐다

**눈여겨볼 것** — 사이드바와 현재 위치는 아무도 만들지 않았습니다.
기획서 목차(IA 트리)에서 자동으로 생성된 것입니다.
표의 내용도 명세에 적혀 있지 않습니다. 열 이름만 보고 만들어진 값입니다.

---

## 7. AI가 못 하는 것을 넘기는가 (Phase 6)

**왜 확인하나** — AI가 억지로 맞춘 이상한 화면을 내놓지 않는지 봅니다.

**어디서** — **화면 하나** 탭

**무엇을 하나** — 왼쪽 글상자를 전부 지우고 아래를 붙여넣습니다.

```json
{
  "archetype": "handoff",
  "header": { "title": "배송 경로 지도" },
  "reason": "지도 위에 경로를 그리는 화면은 기존 원형으로 표현할 수 없습니다.",
  "suggestion": "지도 라이브러리를 붙인 전용 화면이 필요합니다."
}
```

**통과 조건**
- "자동 생성하지 않았습니다" 라는 안내와 이유가 나온다
- 억지로 만든 엉뚱한 화면이 나오지 않는다
- "다음 절차" 안내가 함께 나온다

API 키가 있다면 이렇게도 해보세요. 화면 만들기 칸에
`칸반 보드로 업무를 옮기는 화면` 이라고 쓰고 생성을 눌러보면,
AI가 스스로 못 한다고 답하는지 볼 수 있습니다.

---

## 8. AI 도구가 이 라이브러리를 아는가

**어디서** — 배포 주소 뒤에 `/llms.txt` 를 붙여 접속

**통과 조건**
- 글로 된 설명서가 나온다
- 부품마다 "쓸 때" 와 "쓰지 말 때" 가 적혀 있다
- 원형 7종(list, detail, form, dashboard, settings, wizard, handoff)이 모두 적혀 있다

이 주소를 다른 AI 도구에 알려주면 우리 부품을 알고 작업합니다.

---

## 문제를 발견했을 때

**화면이 깨져 보인다** — 어떤 디자인·어떤 화면에서 그런지와 함께 캡처를 남겨주세요.

**검사가 빨간 X다** — GitHub Actions에서 실패한 항목을 클릭하면 이유가 나옵니다.
그 화면을 캡처해주세요.

**AI 결과가 이상하다** — 어떤 문장을 넣었고 무엇이 나왔는지 함께 남겨주세요.
대부분 `lib/component-catalog.ts` 의 설명을 다듬으면 개선됩니다.

**원형에 없는 화면이 필요하다** — `docs/EXTENDING.md` 에 추가 절차가 있습니다.
